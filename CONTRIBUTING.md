# Contributing Guide

How to set up, code, test, review, and release so contributions meet our Definition of Done.

## Code of Conduct

Our conduct and decision making processes can be found in our team charter.

## Getting Started

Make sure you are working on our fork of the Wasp repository, and not the main Wasp repository. Discuss with the team before starting to work so that you may match the current development style, which may change depending on the current phase of research.

## Issues & Planning

Small issues that are relevant to others should be mentioned directly to them, but larger or longstanding issues should be submitted into the GitHub repository in as much detail as possible.

## Commit Messages

Commit frequently and describe what has changed in your commit. Be detailed in your commits, but keep commits readable to others who may not be working on that exact piece of code.

## Code Style, Linting & Formatting

Code style has not been standardized yet, but make a clear attempt to make your code understandable and readable through methods such as clear variable naming and frequent comments.

## Definition of Done

Discuss with the team before merging large amounts of code, and if merge conflicts affect any interfaces or others' code, discuss with the affected team members before changing the relevant code.

## Security & Secrets

Do not hard code any secrets you may have, and attempt to avoid committing you personal environment(s).

## Documentation Expectations

If you change any interfaces, update the relevant documentation to reflect the changes. Make sure that comments both inside and outside of your current focus accurately reflect any developments.

## Support & Contact

Our methods of contact and support are outlined in our team charter.
